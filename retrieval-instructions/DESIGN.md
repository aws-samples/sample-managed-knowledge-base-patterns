# Design notes

Why this sample is built the way it is.

Written for someone giving several tenants their own answers from a shared Amazon Bedrock
Managed Knowledge Base. It covers the decisions that aren't obvious from the code, the
alternatives that were weighed, and the service behavior behind them. Behavior described
as observed was seen when the sample was tested, and isn't necessarily documented.

---

## Where isolation comes from

A retrieval instruction changes how an answer is written: its voice, format, conventions,
and policy wording. It doesn't limit which documents the agent retrieves. On a shared
knowledge base with no filter, a Sales Region North customer's return question retrieved
the other regions' addenda, and a question about a firmware issue retrieved the
restricted engineering notes. Isolation has to come from somewhere else.

| Decision                                                              | Why                                                                                                                                                                                                                                                                                                                                                                                   |
| --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **A metadata filter per tenant, built on the server**                 | The filter removed every document outside the tenant's entitlement, including from the `SpeculativeRetrieval` step, which runs on the raw message before planning. `retrievers[].configuration.knowledgeBase.retrievalOverrides.filter` applies to every retrieval step. Alternative: instruction-only isolation, rejected because region tenants retrieved other regions' documents. |
| **The filter comes from the authenticated tenant, never the request** | Amazon Bedrock applies whatever filter the request sends, and IAM has no condition key for it. A caller who can choose the filter can read any tenant's documents. In the sample, only `tenancy.py` and `tenancy.ts` build filters, from a tenant key checked against the instruction spec files.                                                                                     |
| **One shared knowledge base, plus an optional separate one**          | A filter keeps one knowledge base to sync and pay for, but every document needs accurate metadata. A separate knowledge base per tenant isolates by design, but adds a knowledge base and data source per tenant. The sample shows both: the Sales Region South knowledge base indexes only global and South documents, and `multi-kb` queries it with the shared one.                |
| **Answer policies are treated as best effort**                        | "Never mention X" can be paraphrased, and a restricted record that was retrieved can still be named. To keep a fact out of answers, filter out the document that contains it.                                                                                                                                                                                                         |
| **A filter doesn't remove values from shared documents**              | A global policy that lists every region's terms is a document every region tenant is entitled to. A filter can't remove one region's line from it. The corpus has one such overlap on purpose (`conflicts` in `corpus/manifest.json`).                                                                                                                                                |

## Tenant model and metadata

| Decision                                                                   | Why                                                                                                                                                                                                                                                                      |
| -------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **One S3 data source over `docs/`, one folder per scope**                  | The folder shows a document's scope at a glance, and the South knowledge base reuses the same bucket with `inclusionPrefixes`, so nothing is uploaded twice.                                                                                                             |
| **Metadata keys `region`, `audience_team`, and `sensitivity`**             | Underscores rather than hyphens in filter keys. Filters use only `equals`, `andAll`, and `orAll`, because managed knowledge bases don't support `startsWith` or `stringContains`.                                                                                        |
| **Entitlements**                                                           | A region tenant gets global documents plus its own region's, with audience `all`. A team tenant gets every region's documents with audience `all`, plus its own team's. `team-engineering` has no tenant, so any engineering note in a tenant's results is over-sharing. |
| **Distinct values per region**                                             | Each region has its own return window, fee, and support contact, so a leaked value is easy to spot in an answer.                                                                                                                                                         |
| **USD everywhere, and sales regions that aren't countries or AWS Regions** | Regions differ only in how they write dates and amounts, so no region implies a country, and "Sales Region" can't be mistaken for an AWS Region.                                                                                                                         |
| **Sales Region Central answers in Spanish from an English corpus**         | It shows that a persona sets the answer language. Its `retrievalGuidance` says to write search queries in English, because the documents are in English.                                                                                                                 |
| **Tag key `tenant`, with `region.team` values for combined cells**         | Tag values allow dots and instruction names don't, so a combined key such as `sales-region-north.team-support` is named `assistant-sales-region-north-team-support`.                                                                                                     |
| **Ingestion details, as observed**                                         | Ingestion of the 32 small documents took a few minutes. The metadata files count as metadata documents, not documents. `_document_title` equals the file name.                                                                                                           |

## Instructions and their lifecycle

| Decision                                                         | Why                                                                                                                                                                                                                                                                                          |
| ---------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Poll `GetRetrievalInstruction` after every create and update** | Create and update return HTTP 202 and the review runs asynchronously. There's no SDK waiter, so both programs poll every 2 seconds, for up to 10 minutes, until `lastTransitionStatus` leaves `CREATING` or `UPDATING`. Reviews finished in seconds when the sample was tested.              |
| **No version create or update while a review runs**              | A second update or a version create during a review returns HTTP 409 `ConflictException`. During the review, `DRAFT` and `GetRetrievalInstruction` serve the previous content, and pinned versions are unaffected.                                                                           |
| **Version only an `ACTIVE` instruction**                         | A new instruction is `INACTIVE` until its first review passes: applying it fails at send, and so does a version create.                                                                                                                                                                      |
| **A rejected review is fixed in place**                          | A content rejection comes back as 202, then `CREATE_FAILED` with `CONTENT_REJECTED` and the field name. The instruction stays `INACTIVE` and counts toward the quota, so `create-instructions` records it and, on the next run, updates it with the edited text instead of creating another. |
| **Validate inputs before sending them**                          | Empty or whitespace-only fields fail synchronously with HTTP 400. Names are 1 to 100 characters matching `([0-9a-zA-Z][_-]?){1,100}` (no dots or spaces), descriptions 1 to 200, and the fields 24,000 characters in total. The programs check the spec files against these limits.          |
| **A quota guard before every create**                            | The default quota is 50 instructions per account and Region (adjustable), and 50 versions per instruction. `create-instructions` counts the account's instructions and refuses to start if the ones it needs don't fit.                                                                      |
| **Version selector `DRAFT` or a number**                         | The selector is `DRAFT` or `[1-9][0-9]{0,8}`. Omitting it applies `DRAFT`, and the trace reports `"DRAFT"`. The programs omit the field for `DRAFT`, as the post's snippet comment says.                                                                                                     |
| **An update resends every field and the description**            | An update replaces the whole instruction, and an update without a description clears it. Version reads return no description, so `support-v2` reads the current instruction first.                                                                                                           |
| **Teardown deletes versions, then the instruction**              | `DRAFT` can't be deleted on its own, version numbers are never reused, and deleting an instruction that still has versions returns 409. Teardown guards every delete by name and by the `app` tag, and waits out any review first.                                                           |

## Composition: a user in a region and a team

A request can reference one retrieval instruction. A support agent in Sales Region South
needs the support team's voice and the region's formats.

| Decision                                                                             | Why                                                                                                                                                                                                                                                                                    |
| ------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Default: the team's instruction, the region's tenant line, and the cell's filter** | N regions and M teams need N + M instructions. The tenant line names the region so the answer quotes its values, and the filter for the region and team cell keeps retrieval to that cell. The team's formats apply.                                                                   |
| **Combined instructions only where formats differ, behind `--combined`**             | One instruction per region and team pair applies the region's formats, but costs N x M more instructions on top of the N + M, so 15 for 3 regions and 3 teams. Alternative considered: combined cells by default, which would use 11 of the default quota of 50 for this sample alone. |

## Releases

| Decision                                                  | Why                                                                                                                                                                                                                                  |
| --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **The application owns routing**                          | Amazon Bedrock serves the version a request pins and doesn't route between versions. Each tenant has a release configuration (a live version and an optional canary) in `sample-state.json`. Promotion and rollback are pin changes. |
| **Pin versions on every request**                         | A pin fixes the instruction, not the wording of each answer, so gate a promotion on your own checks.                                                                                                                                 |
| **Pins are checked against the versions the sample made** | A pin to a version that doesn't exist fails at send with `ValidationException` (400) and no events, while `GetRetrievalInstruction` returns `ResourceNotFoundException` (404). `release set` accepts only recorded versions.         |

## What stays the application's job

- **Exact values.** Date arithmetic in an answer can be wrong, so compute values such as a
  return deadline in your application.
- **Format checks.** Team formats such as the ticket note aren't guaranteed on every
  answer. Validate a format before code depends on it, as `structured-json` does for its
  JSON reply.
- **The tenant.** The service has no notion of a tenant. Mapping an authenticated caller
  to an instruction, a version, a tenant line, and a filter is application code.

## Attribution

| Decision                                                     | Why                                                                                                                                                                                                                                                                                                                                                                                                 |
| ------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Log `appliedInstruction` from the first `Planning` event** | The first `Planning` trace event carries the applied instruction's ID and version. `ask` checks it against the requested version on every call.                                                                                                                                                                                                                                                     |
| **CloudTrail event history for the version, by default**     | Each apply creates a `GetRetrievalInstruction` management event invoked by `bedrock.amazonaws.com` under the caller's session, with the version when one is pinned and none for `DRAFT`. A denied apply logs `AccessDenied`. Events appeared within minutes.                                                                                                                                        |
| **A data-event trail as an option**                          | `AgenticRetrieveStream` isn't in event history. A trail that selects `AWS::Bedrock::KnowledgeBase` data events records it. There's no data-event resource type for retrieval instructions, so the trail's selector names the knowledge base ARN. A test run missed a call made about two minutes after `StartLogging` and recorded the calls made a minute later, so the README waits five minutes. |

## IAM

The tenant roles are optional. They exist only when the stack is deployed with
`trustedPrincipalArn`, for one tenant by default, and `tenantRoles` adds more.

| Decision                                                     | Why                                                                                                                                                                                                                                                                                        |
| ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Apply is authorized on `bedrock:GetRetrievalInstruction`** | `AgenticRetrieveStream` has no resource-level permissions. Applying an instruction needs `bedrock:GetRetrievalInstruction` on its ARN, so the applier's tag condition (`aws:ResourceTag/tenant`) goes there.                                                                               |
| **`TagResource` needs both `RequestTag` and `ResourceTag`**  | With only the request tag, a tenant admin could retag another tenant's instruction into its own scope.                                                                                                                                                                                     |
| **A `KeepSampleAppTag` deny on the tenant admin**            | The tag statement constrains only `tenant`. Without the deny, a tenant admin could change the `app` tag on its own instruction and move it out of the platform admin's scope and past teardown. No role has `bedrock:UntagResource`, so the tag can't be removed either.                   |
| **Creating with tags needs `bedrock:TagResource`**           | The tenant admin and platform admin get it, with the same tag conditions as their create.                                                                                                                                                                                                  |
| **`Retrieve` scoped to each role's knowledge bases**         | Apply permission doesn't limit retrieval, which is authorized separately as `bedrock:Retrieve`. The applier also has `bedrock:GetDocumentContent` on the same knowledge bases, as the agentic retrieval documentation lists. No model-invoke statement: every call uses the managed model. |
| **`ListRetrievalInstructions` on `*`**                       | It can't be scoped by resource or tag, so instruction names mustn't hold sensitive information.                                                                                                                                                                                            |
| **A role per tenant, trusting one named principal**          | Each role trusts the account root with an `ArnEquals aws:PrincipalArn` condition on `trustedPrincipalArn`, with a one-hour maximum session. The one-role-with-a-tenant-session-tag variant is untested, so the sample doesn't build it.                                                    |
| **The platform admin outside the per-tenant construct**      | Adding a tenant adds two roles and never touches the platform admin, and no role has a fixed name, so adding a tenant can't collide.                                                                                                                                                       |

These statements follow a structure that was tested against the service: the applier
could apply its own tenant's instruction and was denied another tenant's, the tenant
admin could create an instruction for its own tenant and was denied retagging another
tenant's instruction into its own scope, and the platform admin could read every
tenant's instruction. Two parts are additions to that structure: the
`aws:RequestTag/app` condition on the tenant admin's create, and the `KeepSampleAppTag`
deny, which stops a tenant admin from moving its instruction out of the platform admin's
scope by changing the `app` tag. `verify-abac` checks the deny. It doesn't check the
tenant admin's create path, because a create would use quota.

## Infrastructure

| Decision                                                         | Why                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ---------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **CDK owns the knowledge bases; SDK code owns the instructions** | CloudFormation has `AWS::Bedrock::RetrievalInstruction`, and a stack create waits for the review, but it has no version resource. Versions created outside the stack block its deletion (the delete fails with 409 after a few minutes). `Name` and `CustomerEncryptionKeyArn` force replacement. The post teaches the SDK lifecycle, so the instructions, versions, and pins live in the programs, and `teardown` deletes them before `cdk destroy`. |
| **Typed L1 `CfnKnowledgeBase` and `CfnDataSource`**              | Both have the managed properties at the pinned aws-cdk-lib. `connectorParameters` is a JSON object, not a string.                                                                                                                                                                                                                                                                                                                                     |
| **`aclEnabled: false`**                                          | Isolation here comes from metadata filters, not `userContext` ACLs. With ACLs on, every document would need an ACL entry.                                                                                                                                                                                                                                                                                                                             |
| **A service role per knowledge base, without `grantRead`**       | Each role trusts `bedrock.amazonaws.com` with `aws:SourceAccount` and `aws:SourceArn`, and has `s3:ListBucket` on the bucket and `s3:GetObject` on its own prefixes, both with an `aws:ResourceAccount` condition. `grantRead` would add `s3:GetObject*`, `s3:GetBucket*`, and `s3:List*`. No `bedrock:InvokeModel`: ingestion with the managed embedding model indexed every document without it.                                                    |
| **Prefix scoping covers object reads, not key listing**          | The South role reads only `docs/global/*` and `docs/sales-region-south/*`, but `s3:ListBucket` is bucket-wide, so it can list every key name in the bucket. The key names hold nothing beyond the folder and file names.                                                                                                                                                                                                                              |
| **`BucketDeployment` with `retainOnDelete: false`**              | It empties the bucket on stack deletion without the extra auto-delete function, its role, and its managed policy.                                                                                                                                                                                                                                                                                                                                     |
| **Ingestion starts on deploy**                                   | An `AwsCustomResource` calls `StartIngestionJob` after the upload, and again when the corpus fingerprint changes. Managed parsing and embedding have no line item, so starting the job adds no charge. `status --wait` waits for it, so the deploy doesn't need a polling function. Alternative: an explicit `ingest` command in both languages.                                                                                                      |
| **Stack-owned log groups, deleted after the roles**              | The two CDK handler functions get one-week log groups that the stack owns. Every role depends on them, so a late log event can't recreate a group after deletion, and `cdk destroy` leaves none behind.                                                                                                                                                                                                                                               |
| **The app reads `AWS_REGION` itself, default `us-east-1`**       | It matches the post's client snippet, so the stack and the commands can't land in different Regions because a profile sets another Region. Alternative: `CDK_DEFAULT_REGION`, which falls back to the profile Region.                                                                                                                                                                                                                                 |
| **A concrete account at synth**                                  | The account comes from the CLI's credentials, or from `-c account=` for a synth without them. The cdk-nag acknowledgments match literal ARNs only, so a token account would fail synth with unacknowledged findings; an explicit error says so first.                                                                                                                                                                                                 |
| **Literal partitions, and the recommended feature flags**        | `@aws-cdk/core:enablePartitionLiterals` makes the ARNs readable and lets one strict pattern match them. The rest of the context in `infra/cdk.json` is the recommended flag set the sibling patterns use, including `validateAgainstDefaultRules`.                                                                                                                                                                                                    |
| **Fixed names that can't collide with your resources**           | The stack is `RetrievalInstructionsSample`, the knowledge bases start with `retrieval-instructions-sample-`, and the instructions with `assistant-`. `create-instructions` refuses to start if one of its names exists without being in its state file. One deployment per account and Region is supported.                                                                                                                                           |
| **Optional parts are context switches**                          | `trustedPrincipalArn` turns on the tenant roles, and `southKnowledgeBase=false` turns off the South knowledge base. The core walkthrough needs neither, so `npm run deploy` takes no context.                                                                                                                                                                                                                                                         |

Managed knowledge bases have two behaviors worth knowing when you adapt this. `Retrieve`
rejects `vectorSearchConfiguration`; use `managedSearchConfiguration`, which also takes
filters. And a knowledge base created right after its service role can fail while IAM
propagates; deploy again.

### cdk-nag acknowledgments

cdk-nag v3 runs inside synth through `Validations.of(app).addPlugins`, so an
unacknowledged finding fails `cdk synth`. Every acknowledgment is in
`infra/lib/nag-acknowledgments.ts` or the role constructs, on the narrowest construct,
with a written reason. The IAM5 wildcards are acknowledged by exact finding, so a new
wildcard fails synth.

| Finding                                                            | Where                                 | Reason                                                                                                                      |
| ------------------------------------------------------------------ | ------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `AwsSolutions-S1` (no server access logging)                       | The corpus bucket                     | It holds the fictitious corpus and is deleted with the stack. A logs bucket would fill with log objects and block deletion. |
| `AwsSolutions-IAM5` on `<bucket>/docs/*` and the South prefixes    | The knowledge base service roles      | The data source crawls every object under its prefixes, so the keys aren't known when the policy is written.                |
| `AwsSolutions-IAM5` on `retrieval-instruction/*`                   | The tenant and platform admin roles   | Instructions are created after deployment. Every statement on this resource has a tag condition.                            |
| `AwsSolutions-IAM5` on `Resource::*`                               | Applier, tenant admin, platform admin | Only for `bedrock:AgenticRetrieveStream` and `bedrock:ListRetrievalInstructions`, which can't be scoped.                    |
| `AwsSolutions-IAM4` (`AWSLambdaBasicExecutionRole`)                | The two CDK handler functions' roles  | CDK's handlers use the managed policy that only grants writing their own logs.                                              |
| `AwsSolutions-IAM5` on the CDK assets bucket and the corpus bucket | The `BucketDeployment` handler only   | It copies the corpus from the CDK assets bucket and deletes it on stack deletion.                                           |
| `AwsSolutions-L1` (not the latest Lambda runtime)                  | The `BucketDeployment` handler only   | AWS CDK manages the handler's runtime.                                                                                      |

## Structured JSON

| Decision                                       | Why                                                                                                                                                                                                                                                                                                                          |
| ---------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **An instruction with only an `answerFormat`** | It asks for one JSON object with five keys, and the request uses a filter for public documents so internal notes stay out. Alternative: a retrieve-only call plus your own model call. Both gave valid JSON about as often in testing. The managed path was slower, and it uses the managed model instead of one you choose. |
| **Validate the reply strictly**                | `structured-json` checks the keys, their types, and the `confidence` values, and exits 1 on any difference. A format instruction isn't a schema guarantee.                                                                                                                                                                   |

## Code and tooling

| Decision                                                           | Why                                                                                                                                                                                                                                                                                                                               |
| ------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Python and TypeScript with the same commands and output**        | The post shows Python, and the sample serves TypeScript readers too. The formatters in `formats.py` and `formats.ts` are tested against the same expected output in `test-fixtures/expected/`, so the two can't drift. Help text and usage-error wording can differ; exit codes can't.                                            |
| **One state file, `sample-state.json`, at the pattern root**       | Both programs read and write it, so you can create instructions in one language and ask in the other. It records the account, the Region, each instruction's ID and versions, and the release pins. Writes are atomic, and both languages write identical bytes for the same content. There's no lock, so don't run both at once. |
| **Knowledge base IDs from the stack outputs, every time**          | One source of truth that can't go stale after a redeploy.                                                                                                                                                                                                                                                                         |
| **Two senders and one filter module**                              | `ask_as_tenant()` is the post's snippet, for a request with a tenant line and a pinned version. `send_request(build_request(...))` sends the rest. Both accept a filter only as the `TenantFilter` type that `tenancy` creates.                                                                                                   |
| **`StreamResult`, kept small**                                     | `read_stream()` returns the applied instruction, the answer, the response text, the retrieved documents, the first `Planning` event's attributes (for `ask --trace`), and any exception raised mid-stream. Both SDKs raise modeled exception events during iteration rather than yielding them.                                   |
| **Exception codes in one form**                                    | botocore names an in-stream exception after its event (`accessDeniedException`). The Python reader capitalizes it to the exception name the JavaScript SDK uses (`AccessDeniedException`), so messages match.                                                                                                                     |
| **A long read timeout and standard retries on the runtime client** | A stream call can run from several seconds to about a minute. Both programs allow 120 seconds without data. botocore counts `max_attempts` as retries, so Python makes up to 6 attempts and TypeScript up to 5; only the initial request is retried.                                                                              |
| **No retry on `ConflictException`**                                | Every path waits for the review before it versions, updates, or deletes, so a conflict means another process changed the instruction. It's reported with the service's message.                                                                                                                                                   |
| **`pyproject.toml` at the pattern root, code under `python/src`**  | Every command runs from the pattern directory. uv with the `uv_build` backend; ruff, `mypy --strict` targeting Python 3.10, and pytest.                                                                                                                                                                                           |
| **No boto3-stubs**                                                 | With stubs, the post's dict literals fail strict type checks unless they're annotated, which would change the snippet lines. botocore's `Stubber` validates every request in the tests against the real service model instead.                                                                                                    |
| **`node:util` `parseArgs`, no CLI dependency**                     | Both parsers reject abbreviated options (argparse with `allow_abbrev=False`), so `--ques` is a usage error in both.                                                                                                                                                                                                               |
| **Request building, parsing, and formatting have no AWS calls**    | They're unit-tested directly. The TypeScript tests replace `send` on real client instances, because the SDK paginators check the client class.                                                                                                                                                                                    |

| Common choice                                              | This sample                                                                                                                | Why                                                                                                                                                                                                                                                                                                                       |
| ---------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A Python project in its own subdirectory                   | `pyproject.toml` and `uv.lock` at the pattern root, code under `python/src`                                                | Every command in the README runs from the pattern directory, in both languages.                                                                                                                                                                                                                                           |
| `uv sync --frozen` in CI                                   | `uv sync --locked`                                                                                                         | It fails when `pyproject.toml` and `uv.lock` disagree, the same check `npm ci` makes.                                                                                                                                                                                                                                     |
| Locking only `boto3`                                       | `boto3` and `botocore` both locked at 1.43.118                                                                             | The post's snippets say "Checked with Boto3 1.43.118". botocore holds the service models, so locking it too keeps the models the code was checked against.                                                                                                                                                                |
| No interpreter pin                                         | `.python-version` 3.13                                                                                                     | One default interpreter for local runs and CI. The tests also run on Python 3.10, the minimum the post states.                                                                                                                                                                                                            |
| A JSON-format instruction without a tenant tag             | `assistant-structured-json` is tagged `tenant=structured-json`                                                             | Every sample instruction then carries the same two tags, so the platform admin's conditions and the teardown guard treat them all the same way.                                                                                                                                                                           |
| Tenant roles deployed with every stack                     | The tenant roles are created only when you pass `trustedPrincipalArn`, for one tenant by default (`tenantRoles` adds more) | The walkthrough doesn't use the roles, so the first deploy needs no role ARN. CloudFormation also runs as the CDK deployment role, so a lookup during deployment would trust the wrong role. An explicit ARN is visible in the deploy command. |
| A check script for apply-own, apply-other, and retag-other | `verify-abac` runs five checks                                                                                             | The two extra checks cover the platform admin's reach (it can read another tenant's instruction) and the tenant admin's `app` deny. None of the five creates an instruction, so the check uses no quota.                                                                                                                  |
| A generic project tag                                      | `app=retrieval-instructions-sample` on everything the sample creates                                                       | One tag finds everything the sample created, and the platform admin's conditions and the teardown guard use the same tag.                                                                                                                                                                                                 |
| Answer keys in the corpus manifest                         | The manifest lists each document's metadata and its `conflicts`, with no expected answers                                  | The conflicts document the overlaps between documents on purpose. The sample checks behavior with the `isolation` command instead of answer keys.                                                                                                                                                                         |
| High-resolution figure exports                             | `docs/images/` holds the 1x PNGs and the SVGs                                                                              | The SVGs scale, and the post hosts its own copies.                                                                                                                                                                                                                                                                        |
| The latest provider runtime for every Lambda function      | `AwsSolutions-L1` acknowledged on the CDK `BucketDeployment` handler                                                       | AWS CDK sets that handler's runtime, so the stack can't choose it.                                                                                                                                                                                                                                                        |

## Out of scope

- **`userContext` ACL filtering.** It needs an ACL-enabled data source, and the other
  patterns in this repository cover it.
- **One role with a tenant session tag.** Untested, so the sample uses a role per tenant.
- **A KMS key for instructions.** `customerEncryptionKeyArn` is documented in the README
  and not used, because it can only be set at create and adds a standing cost.
- **Custom embedding models.** The knowledge bases use the managed embedding model, so
  there's nothing to tune.
- **Instructions as CloudFormation resources.** See [Infrastructure](#infrastructure).
